## Mechanical Sympathy & go-disruptor Architecture Analysis (Updated 2026-10-12)
Per user binding rule `.agents/rules/anti-toy-and-zero-complacency.md`:
1. **Current Ingest Path Defects**:
   - `internal/pkg/logengine/writer.go:128-175`: Inverted Mutex Anti-Pattern. `Write(entry)` holds `w.mu.Lock()`. When rowCount >= 2048, `flushLocked()` executes synchronously inside the lock: zstd compression, `os.MkdirAll`, 4 binary file writes, `os.Rename`, and `dict.SaveToFile`. All other container tailers calling `Write()` block on `w.mu.Lock()`.
   - `internal/infrastructure/clickhouse/batch_writer.go:162-180`: Multiple producers contend on `w.mu.RLock()` and Go runtime `hchan.lock`. Under high volume, `select default` with nested pop-drop generates CPU spin and lock contention.
2. **Disruptor Application (MPSC Ingest Ring Buffer)**:
   - **Mechanism**: Lock-free power-of-2 ring buffer with 64-byte cache-line padding to eliminate False Sharing between CPU cores. Concurrency controlled via atomic sequence barriers (`sync/atomic`).
   - **Allocation Profile**: Zero runtime heap allocations (`0 B/op`, `0 allocs/op`) on ingest. Memory allocated once at bootstrap.
   - **Hardware & Failure Mode Constraints**:
     - *CPU Throttling Risk*: Default LMAX `BusySpinWaitStrategy` consumes 100% of a CPU core in tight loop. On Kubernetes nodes or self-hosted agents with small CPU limits (100m-200m), this causes immediate CPU throttling.
     - *Mandatory Fix*: Must implement **Hybrid / Yielding Wait Strategy** (batch scan when saturated, `runtime.Gosched()` / `sync.Cond` when idle).
     - *Ring Wrap-around Risk*: Disruptor only buffers in memory. If disk/network I/O is slower than ingress rate, sequence barrier will block producers or overwrite oldest entries (backpressure required).
     - *Mechanical Sympathy*: Disruptor decouples the CPU-bound ingress path from the I/O-bound disk flusher.
