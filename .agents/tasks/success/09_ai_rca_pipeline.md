# Objective
Refine the Artificial Intelligence components. The current LLM integrations (OpenAI, Claude, Gemini) and the Root Cause Analysis (RCA) worker over NATS must be optimized for reliability and token efficiency.

# Scope
`internal/usecase/ai`, `internal/usecase/rca`, `internal/infrastructure/llm`, `internal/infrastructure/nats`

# Tasks
- [x] **Prompt Engineering**: Audit all prompts in the RCA pipeline. Ensure they are context-aware (feeding them real logs/metrics from Phase 3) and prevent AI hallucinations.
- [x] **NATS Streaming Resiliency**: Enhance the RCA Worker listening on NATS. Ensure messages (events from Kubernetes) are properly acknowledged (Ack) or re-queued (Nak) if the LLM provider times out.
- [x] **Circuit Breaker Tuning**: Review `llm.NewCircuitBreakerClient`. Adjust timeout and failure thresholds to instantly fallback to secondary models (e.g., from GPT-4 to Claude 3.5) without blocking the UI.
- [x] **AI Health Poller**: Optimize the background `HealthPoller` to avoid spamming the LLM APIs and racking up API costs during idle times.

# Acceptance Criteria
- RCA reports generated by the AI are deterministic and based on real cluster telemetry.
- NATS queue handles spikes in cluster events gracefully without crashing the Go worker.
- LLM API costs are minimized through intelligent caching and polling backoffs.
